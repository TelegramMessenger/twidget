# twidget in safe Rust

The port of everything Telegram's widget helper runs to Rust without `unsafe`, compared with the C++ at
every stage. `PLAN.md` has the goal, the rules, the stages and where they stand.

| Path | What |
|---|---|
| `crates/wire` | `twidget_wire`: the paint values and their binary forms (`core/src/wire.cpp`) |
| `crates/paint` | `twidget_paint`: heavy boxes, the paint limit and its ledger (`core/src/paint_policy`) |
| `crates/remote` | `twidget_remote`: the messages between the renderer end and the platform end (`core/src/remote.cpp`) |

| `crates/computed_style` | `twidget_computed_style`: the `cs` query's strings, getComputedStyle as Chromium writes it, from what the fork computed for an element (`core/src/computed_style.cpp`), made from the Rust litehtml's cascade and render tree but for the layout boxes |
| `crates/css` | `twidget_css`: TwidgetCore's small CSS helpers (`core/src/css.cpp`) |
| `crates/cstd` | `twidget_cstd`: the C library behaviours the C++ leans on (`strtod`, `strtof`, `strtol`, `atof`, `atoi`, `%.*f`, `%g`) |
| `crates/compositor` | `twidget_compositor`: layers and their baked tracks, paint digests, damage, inert clips (`core/src/compositor.cpp`) |
| `crates/base64` | `twidget_base64`: the base64 of canvas pixels (`core/src/encode.cpp`) |
| `crates/filters` | `twidget_filters`: CSS filter functions for painters: colour matrices, a chain's reach, the CPU pass over pixels (`core/src/filters.cpp`) |
| `crates/png` | `twidget_png`: the rows of a damaged PNG a browser keeps, and the size an image header declares (`core/src/png.cpp`) |
| `crates/encode` | `twidget_encode`: the JSON forms of a display list, a canvas batch and a composition, for painters outside C++ (`core/src/encode.cpp`) |

| `crates/renderer` | `twidget_renderer`: the renderer: host messages in, the document built from the widget's ops and patched in place where the fork can (its holes, its style holes, the serialised HTML), the coalesced batch and the viewport that follows the document, the layout budget and the name table's bounds that stop a widget, `frozen` and its badge, the theme and the safe area with the master CSS made from them, the size reports and resize diffs, animation overrides, every query kind with its `result`, and stage 4.5 (`layers.rs`): the paint policy's heavy boxes counted and the paint and backdrop stops, the compositor layers (movers, nested, shimmer, scripted, SVG, canvas and still layers, clips, coverage, the cap), scripted layers moved without a build, the paint with each layer's content kept or drawn again, the list handed out again, the damage between paints, hits through layers; the shadow tree and the input driven as the C++ drives them, over an `Engine` trait for litehtml's document, its paint and what the layers read of it (`core/src/renderer.cpp`) |
| `crates/ends` | `twidget_ends`: the two ends over a byte channel: `RendererEnd` with its Backend proxy over a `Renderer` trait, and `PlatformEnd` (`core/src/renderer_end.cpp`, `platform_end.cpp`) |
| `crates/litehtml` | `twidget_litehtml`: the litehtml fork a stage at a time, one module per C++ file (`litehtml/src`); so far `pixel_t`, the name table, strtod, `web_color`, `css_length`, the keyword tables, the CSS tokenizer and parser, stylesheets with their at-rules and media queries, selectors and their matching, style blocks (`style.cpp`: every property's declaration as the typed with spans and the cell budget, `list_index`, each element's render items as weak references), block and inline layout (`render_item.cpp`'s `render` with the layout cache, its marks and the layout budget, `render_block`, the block and inline formatting contexts, floats and clearance, margins collapsing, line boxes with the container's text breaker, white space, `text-overflow: ellipsis`, bidi placements; `render_fixed_only` and `render_no_fixed`), table layout (`render_table.cpp`'s `_render` and `table.cpp`'s grid: cells measured for their columns' minimum and maximum widths, spanning `repeat()`, `auto-fill` and `auto-fit`, rows from `grid-template-rows` and `grid-auto-rows`, placement by lines and spans and sparse auto-placement under its cell budget, column sizing from the items' min- and max-content widths with `minmax()`, `fit-content()` and `fr` shares, `fr` rows in a definite height, gaps, `justify-content`, `align-content`, `justify-self` and `align-self` with stretch paint groups with opacity, transforms, filters, backdrop filters and clip paths, overflow clips with radii, fixed boxes escaping clips, culling by each item's ink and the paint trace; outlines and list markers; texts with their ellipses, the form controls' drawing, tables' rows, cells and collapsed borders: every paint call of `document_container.h` in the C++'s order with its | `crates/litehtml/src/gumbo` | `twidget_litehtml::gumbo`: Gumbo, the HTML parser the fork parses with (`litehtml/src/gumbo`), one module per C file: the UTF-8 reader, character references with char_ref.c's Ragel machine, the tokenizer, tree construction and its limits |

| `oracle/` | the C++ the port is compared with: small programs built from twidget's sources, cases on stdin; `lhdump` answers for the litehtml fork, stage by stage (with render_grid.cpp copied and probed to record each grid pass, `lhdump_grid.h`, every paint call logged with its arguments, `lhdump_paint.h`, and the pointer's steps, `lhdump_hit.h`), `svg_oracle` for el_svg.cpp's geometry (its painting through `lhdump`'s paint calls), `events_oracle` for the renderer's input (renderer.cpp copied with probes at the input code's calls, `events_oracle.cmake`), `renderer_oracle` for the renderer (the same copy with probes at its calls into the document and the container, stage 4.5's included, `renderer_oracle.cmake`; the shared mechanism in `probe.cmake` and `input_probes.cmake`) |
| `tools/gate.py` | the gate: oracle build, `cargo test` with the comparison required, clippy, rustfmt, `unsafe` report |
| `tools/unsafe_report.py` | `unsafe` in the workspace and in every crate it links; `#![forbid(unsafe_code)]` on every root |
| `tools/gen_gumbo_tables.py` | writes `gumbo/tables.rs` and `tag_enum.rs` from Gumbo's C sources (the tag tables and char_ref.c's machine); `tests/gumbo.rs` checks them against the C |

```sh
python -I tools/gate.py            # add --release to run the tests optimized too
cargo test                         # without the oracle: the comparison tests skip
TWIDGET_ORACLE_DIR=oracle/build/Release TWIDGET_ORACLE_REQUIRED=1 cargo test   # what the gate runs
```

The oracle needs a C++20 compiler, CMake (`cmake -S oracle -B oracle/build`) and widget-sandbox next to
twidget (`-DTWIDGET_WIDGET_SANDBOX=` elsewhere); the JSON tests read its files the same way
(`TWIDGET_WIDGET_SANDBOX`). On the Telegram
machines the toolchain is `ThirdParty/rust` (`RUSTUP_HOME`, `CARGO_HOME`); nothing here pins it.
